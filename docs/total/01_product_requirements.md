## 1. 产品定位

构建一个面向个人技术学习与项目资料管理的网页 AI 工作台。用户在一个聊天界面中，可以使用自己的文档、关键词搜索、知识图谱和互联网资料完成问答、定位、比较与研究。

产品的核心不是“能够调用大模型”，而是：

**围绕一个问题，选择合适的信息来源，展示可检查的证据，并保留完整、可继续使用的会话。**

完整首版应覆盖四路检索：

| 检索方式 | 用户想解决的问题 | 典型输入 | 用户应看到的结果 |
|---|---|---|---|
| 直接搜索 | 某个词、函数、错误码出现在哪里 | 搜索 `"CommitOffset"` | 文件、匹配片段、真实定位信息 |
| 语义检索 | 文档中哪些内容与问题含义相关 | 项目如何避免重复消费 | 相关段落及据此生成的回答 |
| 图谱检索 | 实体之间有哪些有来源的关系 | 消息表、Outbox、消费者如何关联 | 局部关系图、关系说明、支撑原文 |
| 联网搜索 | 外部公开资料或时效信息是什么 | 查官方更新并与我的笔记比较 | 网页来源、访问时间、正文依据、比较结论 |

“RAG”在产品界面中可作为语义知识库问答的名称；严格来说，检索增强生成是一整条流程，不只是向量检索。直接搜索、图谱和联网资料也可以参与生成。

**直接搜索不是执行任意命令。** `/grep` 等快捷输入只是受控的搜索入口，不能访问宿主机任意路径，也不能运行 Shell。

## 2. 用户、场景与目标

### 2.1 目标用户

首要用户是项目开发者本人，主要使用中文技术笔记、项目文档和少量英文官方资料。其次是演示时的测试账号。首版保留账号和数据归属概念，但不建设组织架构、计费和公开注册体系。

| 身份 | 可以做什么 | 不应该做什么 |
|---|---|---|
| 普通用户 | 管理自己的会话、项目和知识库；运行已授权工具 | 查看其他用户资料、读取服务密钥、修改系统工具权限 |
| 管理员 | 配置模型、联网、配额和功能开关 | 通过普通页面明文展示已有服务密钥 |
| 系统执行器 | 按当前用户权限调用工具并形成回答 | 因网页、文档或模型指令而自行扩大权限 |

### 2.2 主要使用场景

| 场景 | 用户操作 | 期望价值 |
|---|---|---|
| 技术资料问答 | 上传笔记后围绕一个主题连续提问 | 不必手动翻找多份资料 |
| 精确定位 | 搜索某个函数名或配置项 | 明确知道原文在哪里，而非只得到解释 |
| 项目关系梳理 | 查询几个服务、组件之间的联系 | 看见有原文依据的关系，而不是未经验证的关联 |
| 新旧知识比较 | 同时指定本地知识库和联网搜索 | 分清旧资料、当前资料以及版本适用范围 |
| 持续学习 | 将多个会话归入一个项目 | 保持项目说明、知识范围和历史连续性 |
| 可选代码验证 | 在隔离环境中运行生成的短程序 | 把模型建议与实际执行结果分开呈现 |

### 2.3 首版成功标准

首版应形成“上传资料 → 检索 → 回答 → 查看来源 → 继续追问”的完整闭环。四路检索都有独立入口，也能在授权范围内组合使用；任一路不可用时，系统明确提示，不能伪装为成功。

图谱是否带来价值，要通过具体关系问题的证据覆盖情况判断，而不是只看图是否漂亮。系统不承诺所有问题都能回答，也不承诺图谱一定优于普通检索。

## 3. 范围与优先级

优先级定义：

| 优先级 | 含义 |
|---|---|
| P0 | 完整首版必须具备 |
| P1 | 完善体验和工程深度；P0 闭环完成后实施 |
| P2 | 可选扩展，不阻塞核心产品交付 |

### 3.1 功能范围总表

| 模块 | P0：首版核心 | P1：增强 | P2：可选 |
|---|---|---|---|
| 聊天 | 流式回答、停止生成、错误提示、Markdown | 更丰富的消息内容块 | 多模态输入输出 |
| 会话 | 新建、重命名、删除、历史持久化、重新生成 | 编辑旧消息、分支导航、全文搜索 | 分享和协作 |
| 项目 | 项目说明、绑定知识库、会话归属 | 项目配置模板 | 跨项目工作流 |
| 知识库 | 上传、处理状态、删除、更新、原文查看 | DOCX、更多解析方式、批量管理 | 外部平台自动同步 |
| 检索 | Direct / RAG / Graph / Web，手动与自动入口 | 自适应二次检索、查询改写优化 | 更复杂的研究流程 |
| 来源 | 段落引用、网页来源、引用核验 | 证据对比、引用反馈 | 协作审阅 |
| 上下文 | 当前分支历史、项目说明、证据、预算控制 | 历史摘要 | 可管理的长期记忆 |
| Agent | 首版普通问答可用固定流程完成 | 多轮工具调用、运行预算 | 更复杂的规划与人工审批 |
| 可观测 | 运行状态、工具耗时、错误原因、基本用量 | 调试页、评测报告 | 多用户运营面板 |
| 沙箱 | 不属于 P0 | 不属于 P1 前置条件 | 隔离代码执行与产物下载 |

### 3.2 明确不做

首版不做公开多租户 SaaS、付费订阅、移动端原生应用、实时语音视频、通用浏览器自动操作、无限自主运行的 Agent、任意数据库查询，以及面向互联网陌生用户的通用代码执行平台。

网页工作台、四路检索和会话系统完整后，才考虑沙箱。不能因为沙箱尚未实现，就让普通聊天和知识问答无法交付。

### 3.3 对用户可见的系统形态

用户和前端只面对一个 HTTP 入口：浏览器不直连模型、知识索引或图谱存储。

非基础设施进程只有两个，整体不是微服务，详见技术选型与架构文档：

- Go 进程：会话、权限、检索调度、回答生成；唯一对浏览器暴露
- Python 进程：解析、语义索引、图谱构建与查询，全部在这一个进程内完成，不对浏览器暴露

PostgreSQL、Neo4j、文件目录、模型供应商是基础设施或外部依赖，不算第三个产品进程。完整首版覆盖四路检索。图谱是 Python 进程里的模块，不是新的产品入口。Direct Search 面向解析后的标准化文本；PDF 定位按解析片段展示，不假装原文件行号。

## 4. 信息架构与页面设计

### 4.1 主导航

| 页面 | 主要内容 | 默认体验 |
|---|---|---|
| 聊天 | 会话列表、消息区、输入区、来源侧栏 | 打开最近会话或空白新会话 |
| 项目 | 项目说明、关联会话、绑定知识库 | 清楚显示当前项目的数据范围 |
| 知识库 | 文档列表、处理状态、版本、检索测试 | 优先显示失败、处理中和待发布项目 |
| 图谱 | 实体搜索、局部子图、关系来源 | 不自动加载整个知识图谱 |
| 运行记录 | 历次运行的状态、工具事件、用量 | 以问题为入口，而不是以内部日志为入口 |
| 设置 | 模型配置、联网开关、配额、账号 | 不向浏览器返回明文服务密钥 |

### 4.2 聊天页布局

桌面端采用三栏结构：左侧是会话与项目导航，中间是对话，右侧为按需展开的来源或工具详情。窄屏时收起侧栏，保留对话与输入区。

输入区应显示当前模型、项目、知识范围、联网授权状态和运行模式。用户无需打开设置页即可知道“这次回答将访问哪些数据”。

回答旁至少提供复制、重新生成、查看来源和查看运行详情。工具输出默认折叠，只显示工具名称、执行状态及简短结果，不让原始 JSON 淹没正文。

### 4.3 展示原则

普通用户界面使用“查找资料”“读取网页”“生成回答”等可理解状态。调试页可以显示查询改写和候选证据，但不以展示模型隐藏推理过程为功能目标。

加载中、无结果、来源不可访问、权限不足、超时、部分成功必须有不同状态。不得把所有异常统一显示为“AI 正在思考”。

## 5. 聊天与会话需求

### 5.1 会话生命周期

| 编号 | 需求 | 优先级 | 验收要求 |
|---|---|---|---|
| CHAT-01 | 新建、重命名、删除会话 | P0 | 刷新页面后结果一致；删除前确认 |
| CHAT-02 | 历史消息持久化 | P0 | 关闭页面再打开，已保存内容、来源和状态可恢复 |
| CHAT-03 | 流式输出 | P0 | 内容逐步出现，不必等待完整答案 |
| CHAT-04 | 停止生成 | P0 | 立即显示取消中；保留已产生内容并标记“已停止” |
| CHAT-05 | 重新生成 | P0 | 产生新回答版本，不覆盖旧回答 |
| CHAT-06 | 编辑旧问题并分支 | P1 | 原分支保留；新问题只影响新分支 |
| CHAT-07 | 导出当前会话 | P1 | 导出 Markdown，包含所选分支及可访问来源 |
| CHAT-08 | 模型选择 | P0 | 至少一个模型可用；记录每次回答实际使用的模型配置 |
| CHAT-09 | 会话内容搜索 | P1 | 能定位匹配消息并打开其所在会话 |

### 5.2 生成中的行为

一次提交对应一次“运行”。运行状态应区分排队、执行中、取消中、已完成、失败、已停止和超时。

同一会话首版只允许一个活跃运行。用户重复点击提交，不能生成多条相同问题和重复计费请求；可以提示已有任务，或定位回正在运行的回答。

刷新页面或网络短暂断开，不等同于用户主动取消。恢复页面后，应恢复已经保存的输出和真实运行状态。服务异常中断时，不承诺继续同一次模型生成；用户可以明确发起重新生成。

失败回答可以保留已生成片段，但不能显示为正常完成。后续提问默认不把失败片段当作已确认的完整回答。

### 5.3 消息版本与分支

重新生成同一问题时，应出现同一问题下的多个回答版本。编辑历史问题时，应从该问题之前的位置产生新分支，而不是修改旧分支已经发生的历史。

上下文只能使用当前选中分支的历史，不能把相互替代的两个回答版本同时混入模型输入。

## 6. 项目与上下文需求

### 6.1 项目

项目包含名称、说明、默认模型配置、绑定知识库和所属会话。项目说明用于描述任务背景与回答偏好，例如“优先引用项目文档，信息不足时说明缺口”。

修改项目说明影响后续运行，不能悄悄改变已完成回答的历史配置。每次运行应可查看当时使用的项目说明版本和知识范围。

### 6.2 上下文

系统应区分项目说明、当前会话历史、检索证据和可选长期记忆。这些内容不能被混为同一种“知识”。

当上下文过长时，应优先保证当前问题、工具调用与工具结果的完整性，再按预算选择历史和证据。应提示部分历史未带入；摘要是压缩结果，不是原始文档证据。

长期记忆属于 P2。启用后必须支持查看、修改、删除和关闭，不能把系统推测自动永久保存为事实。

## 7. 知识库与文档需求

### 7.1 首版文件范围

P0 支持 UTF-8 TXT、Markdown 和可提取文本的 PDF。P1 支持 DOCX、扫描 PDF 和更多复杂版式。

对于不支持或解析失败的文件，必须说明原因，保留重试或删除入口。不能把“上传成功”展示成“内容已经可以检索”。

PDF 的页码、表格和阅读顺序可能无法完整保留。来源面板必须诚实显示实际具有的定位信息；缺少页码时显示文档和片段，不编造页码。

### 7.2 知识库管理

| 编号 | 需求 | 优先级 | 验收要求 |
|---|---|---|---|
| KB-01 | 创建、重命名、删除知识库 | P0 | 只影响所属用户；有关联会话时先提示 |
| KB-02 | 上传文档 | P0 | 校验格式和大小；上传进度与解析进度分开 |
| KB-03 | 查看处理状态 | P0 | 能区分基础检索与图谱构建的状态 |
| KB-04 | 查看原文件和解析片段 | P0 | 搜索命中能够回到实际内容 |
| KB-05 | 更新文档 | P0 | 处理过程中旧版仍可用；发布后新请求使用新版 |
| KB-06 | 删除文档 | P0 | 新查询立即停止使用已删除文档；后台清理状态可见 |
| KB-07 | 重试失败任务 | P0 | 不重复创建多份业务文档；提示可能产生模型调用费用 |
| KB-08 | 检索测试 | P0 | 可选择检索方式并查看命中片段 |
| KB-09 | 批量上传与批量操作 | P1 | 支持每个文件独立成功或失败 |
| KB-10 | 文档标签与过滤 | P1 | 可按格式、标签和更新时间缩小范围 |

### 7.3 双状态展示

建议把状态拆成两栏：

| 基础检索状态 | 图谱状态 |
|---|---|
| 未上传 / 处理中 / 可用 / 失败 / 删除中 | 未启用 / 排队中 / 构建中 / 可用 / 失败 |

例如“文档问答可用，图谱构建中”是合法状态。图谱失败不应阻止普通知识问答；但不能偷偷用该文档旧版本的图谱替代新版本。

新知识库版本构建较大时，应提示需要重新处理哪些文档，以及可能增加的时间和模型调用成本，而不是暗中重复全量建图。

### 7.4 删除与历史引用

删除文档后，历史答案可以保留，但相应引用应显示“来源已删除或不可访问”。严格删除模式下，历史证据快照和缓存也必须清除，不以“有引用”为理由继续暴露被删除内容。

## 8. 四路检索需求

### 8.1 直接搜索

支持精确字符串、受限正则、文件名和限定文档范围的查询。默认以字面量匹配处理输入，正则由用户明确开启。

结果需要显示命中词、上下文片段、文档名、版本及真实位置。对于转换后的 PDF 文本，要说明定位属于“解析片段”，不能把转换后行号标成原 PDF 行号。

用户要求“找出全部出现位置”时，应提供分页及是否截断的说明，不能只给 Top K 却声称已经列出全部。

### 8.2 语义检索

针对概念、意图和自然语言问题寻找相关片段。结果面板应区分“召回的资料”和“最终回答实际引用的资料”。

资料不足时应明确说明，不得为了凑答案生成不存在的来源。知识库限定模式下，没有证据就是没有证据；是否使用模型一般知识，需要遵守用户选定模式并清楚标识。

### 8.3 图谱检索

支持查找实体、查看一至两跳关联、寻找两个实体之间的受限路径。首版允许少量固定关系查询，不要求用户编写图查询语言。

每个自动抽取关系都需要关联支撑片段。关系来源应标明“文档抽取”，避免把模型抽取结果当成已验证的客观事实。多个来源矛盾时，应保留差异或提示冲突。

图谱界面展示当前问题相关的局部子图。节点过多时应截断、分页或引导用户缩小范围，不直接加载全库。

图谱中没有路径，不代表现实世界没有关系；界面应表述为“当前知识库中未找到有来源的关系路径”。

### 8.4 联网搜索与网页读取

联网搜索和网页读取是不同动作。用户应能看到系统搜索了什么、找到了什么、哪些网页真正被读取。

| 要求 | 产品行为 |
|---|---|
| 联网授权 | 首版默认关闭；用户可按会话开启 |
| 数据外发 | 提示搜索词会发送给外部服务，不自动上传整份私人文档 |
| 仅搜索到摘要 | 可以展示摘要，但应标记“未读取正文” |
| 网页读取失败 | 说明不可访问，不把摘要伪装成全文结论 |
| 时效问题 | 显示来源时间信息；没有发布时间时标记未知 |
| 新旧资料比较 | 明确区分本地版本、网页时间和可能的适用版本差异 |
| 网页收藏 | 只有用户确认后才进入长期知识库 |
| 网页中的指令 | 视为资料内容，不改变工具权限或触发执行 |

### 8.5 手动模式与 Auto

输入框提供 Auto、直接搜索、知识库、图谱、联网五种入口。可提供 `/grep`、`/rag`、`/graph`、`/web` 快捷输入，但不得把它们解释成操作系统命令。

手动模式遵守用户选择：用户只选本地搜索时，系统不能因为本地结果少而自动联网。Auto 可以组合多路，但也必须遵守当前授权、成本上限和知识范围。

不要求每次都查四路。用户可以展开“本次使用的来源”，了解系统实际调用了哪些检索方式。

## 9. 来源与可信回答

### 9.1 来源面板

| 来源类型 | 必需字段 | 有条件展示的字段 |
|---|---|---|
| 本地文档 | 名称、版本、片段、来源是否仍可访问 | 页码、原文行号、标题路径 |
| 网页 | 标题、URL、获取时间、正文或摘要类型 | 发布时间、更新时间 |
| 图谱关系 | 关系描述、相关实体、支撑片段 | 抽取版本、人工确认状态 |
| 代码执行 | 实际输入、退出状态、输出、运行标识 | 产物、资源消耗 |

引用只能指向本次实际取得并允许访问的来源。模型输出一个不存在的引用编号时，系统必须发现并处理，不能直接渲染成看似有效的链接。

### 9.2 回答约束

回答需要区分“来源明确说明”“根据来源作出的推断”和“缺少资料无法确认”。对相互冲突的材料，展示冲突及版本，不自动选择语义分数较高的一条作为真相。

用户限制为“仅依据知识库”时，不得拿联网结果或模型记忆补齐事实后仍标为知识库答案。

## 10. Agent 模式

Agent 模式为 P1。它可以根据任务逐步调用搜索、读取和图谱工具，但必须显示可理解的工具执行轨迹，并具有最大步骤、最大调用次数和总运行时限。

首版普通问答不依赖 Agent；固定检索流程已经可以完成的任务，不必消耗多轮规划。

工具授权由系统决定，不由模型自行决定。网页或文档要求“忽略限制并执行命令”，不得改变实际权限。审批界面属于 P2 沙箱的前置要求之一。

## 11. 可选执行沙箱

沙箱为 P2，仅用于用户明确授权的代码或命令验证，不作为通用远程终端。

| 编号 | 需求 | 验收要求 |
|---|---|---|
| BOX-01 | 执行前确认 | 展示代码、运行环境、时间上限、可访问文件和网络状态 |
| BOX-02 | 环境隔离 | 不能访问宿主机业务目录、服务密钥和其他任务 |
| BOX-03 | 资源限制 | 超时、超量输出或资源超限时终止，并说明原因 |
| BOX-04 | 默认无网络 | 不能因为模型建议而临时获得联网权限 |
| BOX-05 | 结果返回 | 显示退出码、标准输出、标准错误和明确的截断标记 |
| BOX-06 | 产物管理 | 可查看并下载允许的输出文件，下载时再次检查权限 |
| BOX-07 | 生命周期 | 完成或取消后回收执行环境；保留可配置期限的结果 |

P2 首个版本只需实现一种预置运行环境，例如 Python 或 Go。安装任意软件包、后台常驻进程和不受限制的 Shell 均不在首个沙箱版本范围内。

## 12. 非功能需求

以下是供开发与验收使用的默认目标，实际结果必须在指定机器、数据集和模型服务上测量。

| 维度 | 建议要求 |
|---|---|
| 演示规模 | 每库先以不超过 100 份文档、全系统不超过 2 万片段为设计样本，不作为硬性产品上限 |
| 并发 | 单用户最多 2 个活跃运行；同一会话最多 1 个 |
| 文件限制 | 单文件默认 50 MiB，可配置；过大文件在上传前或上传时拒绝 |
| 非模型接口 | 测试环境中，常规列表与详情接口 P95 目标 500 ms 内；不含大文件传输 |
| 流式体验 | 收到上游输出后及时推送；首字耗时单独测量，不承诺由外部模型决定的固定时延 |
| 停止体验 | 点击后 1 秒内展示取消状态；下游停止和清理结果继续可见 |
| 重连 | 恢复已持久化内容；不得因重连重复启动模型生成 |
| 安全 | 未授权跨用户文档、引用、图路径、缓存和产物访问测试必须全部被拒绝 |
| 可恢复性 | 文档任务可重试；异常运行具有终态；重新启动后没有永久“处理中” |
| 可观察性 | 每次运行可定位检索方式、耗时、错误、模型配置和可获得的用量 |
| 隐私 | 明确区分不联网与不外发；即使关闭 Web，云模型仍可能接收用户授权的上下文 |
| 可移植性 | 页面以桌面浏览器为主；开发与演示按 Go、Python 两个进程部署即可，不按能力拆成一串服务 |

## 13. 验收测试清单

| 编号 | 验收场景 | 通过条件 |
|---|---|---|
| ACC-01 | 发送问题后刷新页面 | 已保存的输出恢复；没有重复回答或重复运行 |
| ACC-02 | 连续点击发送两次 | 相同提交被识别；业务只创建一次 |
| ACC-03 | 停止生成 | 终态为已停止；部分内容保留；不再继续启动新工具 |
| ACC-04 | 同一问题重新生成 | 旧回答仍可查看，新回答成为另一版本 |
| ACC-05 | 指定精确词搜索 | 返回实际包含该词的片段和真实位置 |
| ACC-06 | 语义提问不含原文关键词 | 能查看语义召回结果；记录漏召回，不伪造命中 |
| ACC-07 | 关系查询 | 图中关系能打开支撑原文；缺少来源的关系不作为事实回答 |
| ACC-08 | 关闭联网后问最新信息 | 不自动联网；明确说明当前来源范围 |
| ACC-09 | 本地和联网比较 | 两组来源分开呈现，时间和版本不混淆 |
| ACC-10 | 网页只获取到搜索摘要 | 标记未读取正文，不声称已全文核对 |
| ACC-11 | 更新文档但图谱未完成 | 新请求不混入旧图谱；提示图谱暂不可用 |
| ACC-12 | 删除文档后再次提问 | 检索、引用详情和缓存不再泄露其内容 |
| ACC-13 | 伪造别人的会话或文档 ID | 被拒绝，不因知道 ID 而获得访问权 |
| ACC-14 | 文档含有恶意工具指令 | 只作为资料，不执行越权动作 |
| ACC-15 | 检索超时 | 显示部分失败；其他已授权来源按策略继续 |
| ACC-16 | 回答包含虚构引用编号 | 被识别、移除或修正，并保留错误记录 |
| ACC-17 | 超长上下文 | 正常预算裁剪或提示；不破坏工具调用与结果的配对 |
| ACC-18 | 可选沙箱超时与断网 | 任务终止且被回收；不能访问受限网络与文件 |

## 14. 检索质量评测

建立一组固定问题集，不以主观演示效果代替评测。建议初始准备 40～60 个问题，覆盖精确定位、语义问答、关系路径、时效比较、资料冲突和“确实没有答案”。

同一问题应在相同文档版本和模型配置下比较不同检索方式。记录正确证据是否进入候选、是否进入最终上下文、回答是否引用了正确来源、延迟与调用量。

不预先写下“图谱提升 30%”等未经实验的数据。公开展示时使用实际测得结果，并注明数据集范围。

## 15. 产品决策摘要

本项目优先完成可靠的会话、清晰的信息范围、四路检索和可核验来源。自动化程度可以逐步提高，但不能牺牲用户对联网、资料使用和命令执行的控制。

最终演示应该让人看明白三件事：**资料来自哪里，系统实际做了什么，答案在什么范围内可信。**
